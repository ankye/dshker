## 1. Cross-repository protocol

Scope note: this change requires no DeepSeek Harness modification. Harness ships
no `desktop` application profile, descriptor parser, or child IPC counterpart, so
the launcher starts the standard `dsh web --no-open` command and takes readiness
from the URL that process announces. No private-bridge scaffolding ships with this
change; implementing that transport belongs to a separate change owning both
repositories.

- [x] 1.1 [Owner: Integration] Confirm no Harness-side protocol work is required and record the launch contract actually used. Dependencies: none. Evidence: `design.md` records the `dsh web --no-open` decision and the rejected descriptor/IPC alternative; `$DSH_HOME/profiles` has no usable `desktop` profile, `apps/cli/src` exposes no descriptor flag, and `packages/bundle/` ships `web-app` with no `desktop-app`. The undeclared `desktop-harness-client-bridge` capability was retired: its runtime requirements moved into `harness-runtime-supervision`, its renderer limits became the declared `desktop-renderer-authority`, and 1848 lines of unwired descriptor/IPC scaffolding were deleted.
- [x] 1.2 [Owner: Integration] Freeze the readiness contract as the child's own announced loopback URL. Dependencies: 1.1. Evidence: `electron/main/managed/launcher-harness-service.test.ts` accepts the real `dsh web: <url>` line with its credential and rejects non-loopback hosts, non-http schemes, prose mentions, and malformed announcements.
- [ ] 1.3 [Owner: Integration] Record the exact compatible Harness commit and its verification evidence in the Launcher compatibility record. Dependencies: 1.1, 1.2. Blocked on 6.2: no real end-to-end launch has been executed yet, so no commit can be claimed compatible.
