## v0.1.98 tag without a Release

Tag Package run 43145599749 on v0.1.98 (6d6c918) passed every target except
Windows arm64, which failed twice in `runtime:prepare` with
`EPERM: operation not permitted, rename '...\.runtime-stage-*\runtime' ->
'...\resources\runtime'` right after the stage's node.exe ran its smoke tests.
The publish job was skipped, so no v0.1.98 Release exists. The pushed tag is
left in place rather than force-moved; the version moves to 0.1.99, and the
0.1.98 CHANGELOG heading becomes 0.1.99 because it was never published.

`tools/prepare-runtime.mjs` now retries only win32 EPERM/EACCES/EBUSY on the two
directory renames within a fixed 60-second budget, then throws the original
error. Other platforms and other codes fail on the first attempt as before.
Whether the lock is transient on the windows-11-arm image is confirmed only by
the main and tag runs, not locally.
