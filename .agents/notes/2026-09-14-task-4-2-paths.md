# Task 4.2, third slice — the managed layout, containment and the operation lock

Date: 2026-09-14
Change: `go-owned-headless-core` (P4, task 4.2)

## What landed

`paths.go` in `internal/gitcheckout`, ported from
`electron/main/managed/git/paths.ts`:

- **The layout.** `NewInstallationPaths` derives the fixed tree below an
  already-validated Harness namespace — `dsh-launcher/managed-installations/<id>/`
  and, below it, `mirror.git`, `worktrees`, `staging` and `operation.lock` — and
  proves every derived path is contained before returning it, so no caller can be
  handed a path that is already an escape. The installation id is checked against
  the shell's own pattern, because it becomes a directory name.
- **Containment.** `AssertContainedManagedPath` and the walk behind
  `EnsureInstallationDirectories`: only the fixed launcher-owned directories are
  created, one level at a time, and a symlink or an unexpected file at any level is
  refused rather than followed or replaced. `AssertManagedTarget` adds the
  readback for an existing target: it is not a link, its realpath is its own
  spelling, and that realpath is still inside the namespace.
- **The lock.** `AcquireOperationLock` and `OperationLock.Release`: a directory
  (`operation.lock`) created atomically, carrying an `owner.json` written with
  `O_EXCL`, and released only while that record still names this instance. A
  second acquire is `git.operation_locked`; a release that finds someone else's
  record is `git.operation_lock_lost` and leaves the lock alone. The owner
  document is byte-for-byte what the shell wrote, so a lock taken by either
  implementation is recognized by the other.
- **`SameRegisteredPath`** and `ManagedWorktreePath` (a full commit SHA is the
  directory name; an abbreviated id is refused, not expanded).

## One deliberate difference from the shell

The shell's containment test was `!relative.startsWith('..')`, which refuses any
path whose relative spelling begins with two dots — including a sibling directory
legitimately named `..notes`. This compares path elements instead
(`relative != ".."` and no `../` prefix), so such a sibling is contained while a
real escape is still refused. Nothing this layout produces can contain such a
segment, and the target readback is unchanged, so the rule only stops refusing
something harmless. `TestContainmentComparesPathElements` records it.

## Evidence

`paths_test.go`: the derived layout with all five paths, eleven refused
namespaces and ids (relative, non-canonical, root, too short, upper-case,
`../evil`, `evil/child`, a leading dash, over-long); directory creation with the
`0700` mode confirmed on POSIX and a second run proving it is idempotent; the
mirror deliberately _not_ created here; a symlinked namespace, a namespace that is
a file, and a file where a launcher-owned directory belongs, each refused; a
missing target, a real one, and a symlinked one; the lock's owner record pinned by
shape, a second acquire, release, a second release, re-acquire, and a lock taken
over by someone else; the worktree path from a full SHA and four refusals; and
containment, including the sibling above.

Green on the host (`gofmt`, `build`, `vet`, `go test ./internal/... ./cmd/...`),
for `GOOS=windows` and `GOOS=linux`, and on the Windows machine.
