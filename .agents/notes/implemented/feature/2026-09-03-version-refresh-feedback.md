# Version refresh feedback

The three Version management refresh controls now use the same Launcher status-bar feedback and the same visible tab-strip action area. Core refresh reports its remote version-list fetch, Extensions reports managed-source refresh, and Install extension reports its catalog refresh. Core branch selection stays beside the active Core scope, while batch install and uninstall stay with their own tables. Install extension keeps Git and ZIP-package installation beside Refresh, so the catalog list has no persistent source form; a selected ZIP is extracted into a Launcher-owned source before DSH installs it. Each tab starts with a compact scope line and keeps its list in the shared bordered table plane. Each status track is indeterminate because the corresponding main-process operation exposes no measurable completion fraction.

The track uses all remaining status-bar width instead of the former 16rem cap. The label remains visible beside it, so the running operation remains identifiable while all controls stay disabled by their existing pending state.

`versionRefreshFeedback.test.ts` pins the three feedback sources and the uncapped track geometry. The locale catalog supplies distinct Chinese and English labels for core and catalog refresh.

Plugin removal now forwards `--config.offline=true`: an installed profile package is removed from its existing local store and must not wait for an npm registry request. The main process starts every DSH plugin operation as an isolated POSIX process group and bounds it at two minutes; expiration terminates that group and returns the typed plugin-operation failure instead of leaving the renderer busy. The repair path remains DSH-owned: the Launcher deletes its mapped source only after DSH has succeeded.

The installable catalog now uses the dense-operations layout: search and result count remain above the data plane, while categories live in a persistent vertical sidebar and the install table occupies the remaining width. The rail shares the dark canvas with the results instead of becoming a separate muted card; its divider and selected-state indicator retain orientation without competing with data. Catalog provenance is supporting text beneath search. Category filtering preserves the current search and page reset behavior. This replaces the horizontal tag strip, which was difficult to scan and operate once the catalog exposed many categories.
