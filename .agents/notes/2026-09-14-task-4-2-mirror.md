# Task 4.2, fifth slice — the managed mirror and its verification

Date: 2026-09-14
Change: `go-owned-headless-core` (P4, task 4.2)

## What landed

`mirror.go` in `internal/gitcheckout`, ported from
`electron/main/managed/git/mirror.ts`:

- **Creation is staged and published by one rename.** `CreateMirror` (from the
  declared network remote) and `CreateMirrorFromBundle` (from a verified bundle,
  which is how the packaged seed is imported) build the mirror at
  `staging/mirror-<token>.git` and publish it with a single `rename` into
  `mirror.git`, so a reader never observes a half-built mirror. The staging
  directory and the publication directory are proved to be on one filesystem
  first: a rename across devices is a copy, and a copy is not atomic. An
  `init --bare`, the remote, the fetch (or the bundle import into
  `refs/remotes/<name>/*` and `refs/tags/*`), a verification, the rename, the
  containment readback and a second verification make the sequence.
- **Every operation holds the installation lock**, so two of them cannot interleave
  over one installation.
- **`VerifyBareMirror` is the rule the mirror exists for**: it must be bare; it
  must carry exactly the one named remote; that remote must have exactly one URL,
  which must still parse to the confirmed identity; it must configure no
  push-only URL; and it must carry no local configuration that could redirect it —
  no `url.*.insteadOf` and no `include.*`. The fetch happens between two
  verifications, so a configuration changed after the first check is caught by the
  second.
- `FetchMirror` and `InspectMirror` complete the set; `assertPathAbsent`,
  `assertDirectRegularBundleFile` and `assertSameFilesystem` are the three
  refusals they are built from.

## Two things worth recording

1. **`git.repository_not_bare` is narrower than it looks, in the shell and here.**
   Git answers `--is-bare-repository` with `false` only for something that _is_ a
   git directory — so a non-bare `.git` directory reaches the state rule, while a
   worktree root makes git exit 128 and the proof fails earlier as a command
   failure. The port keeps that behaviour rather than reinterpreting it, and both
   codes map to the same renderer code anyway. The test pins both cases.
2. **The network creation path is the one path without a unit test.** Fetching from
   `https://…` would need a real HTTPS remote with a trusted certificate, which a
   test cannot conjure; the bundle path exercises the same sequence with the
   bundle import in place of the fetch, and the fetch invocation itself is the
   only difference. That is also the path production uses for the packaged seed,
   and the one a user-supplied URL would take is covered by the verification rules
   above.

## Evidence

`mirror_test.go`, with real repositories and real bundles:

- a bundle exported from a real repository is imported into a published bare
  mirror: `refs/remotes/origin/main` resolves to the source commit, the tag is
  there, staging is empty afterwards, `InspectMirror` succeeds, and a second
  creation is `git.mirror_exists`;
- a relative, a missing and a directory bundle path are `git.repository_invalid`,
  and a refused creation publishes nothing; a symlinked bundle is refused;
- a creation attempted while another operation holds the lock is
  `git.operation_locked`;
- `FetchMirror` and `InspectMirror` on an installation without a mirror are
  `git.managed_path_invalid`;
- a tampered mirror: another repository's URL, a second remote, a push-only URL
  and a local `url.*.insteadOf` rewrite are each refused
  (`git.remote_mismatch`, `git.remote_mismatch`, `git.remote_mismatch`,
  `git.remote_invalid`), the mirror verifies again once restored, and a non-bare
  git directory is `git.repository_not_bare` while a worktree root is the command
  failure described above.

Green on the host (`gofmt`, `build`, `vet`, `go test ./internal/... ./cmd/...`),
for `GOOS=windows` and `GOOS=linux`, and on the Windows machine.
